## Primary Mechanism Disclosed (Summary of Claims 1–3)

A system that preserves user privacy by receiving prompt data and preprocessing it through tokenization, stop-word removal, stemming, and lemmatization to remove PII. Topic modeling (Latent Dirichlet Allocation or Non-Negative Matrix Factorization) categorizes the processed prompt into semantic topics. A normalized prompt is generated that maintains semantic meaning without sensitive details. Both topic categories and normalized prompts are stored for downstream uses including content recommendations and model training, while original user inputs are discarded.

**Core operation:** NLP statistical preprocessing on natural language prompts. No code-specific handling.

## What This Reference Does NOT Disclose

1. **No AST-level code parsing.** The mechanism operates on natural language prompts via NLP preprocessing (stemming/lemmatization). It has no awareness of code syntax trees, programming language structure, scoping rules, or identifier semantic roles.

2. **No compilability preservation.** Statistical NLP normalization (stemming, lemmatization) inherently destroys syntactic structure — the output cannot be compiled. Project Cloak preserves compilability as a core invariant.

3. **No identifier-to-opaque-token reverse mapping.** IBM's system generates a "normalized prompt" with semantic topic preservation, but there is no bidirectional mapping table enabling a precise restoration of LLM-generated code changes back to original identifiers.

4. **No code patch output or restoration.** The system produces normalized text prompts for storage/recommendation; it does not generate code diffs, apply patches to repositories, or verify patch correctness via a compiler.

5. **No compiler-verified patch loop.** No compile-fail → re-inject → retry mechanism.

6. **No semantic key generation.** The IBM approach discards original tokens (stemming/lemmatization) rather than preserving functional semantic meaning in a structured key attached to the AI call.

7. **No Context Paradox Pattern.** No separation of discovery vs. transmission phases.

8. **No MLP latent bridge.** Entirely prompt-level text preprocessing.

9. **No L2 Egress Filter.** No API gateway enforcement.

## Closest-Claim Overlap Assessment

**Risk area (for attorney review):** This reference has an early priority date (September 2023) and covers the broad concept of "removing sensitive information from LLM prompts before transmission." However, it is weaker prior art than US 12,566,889 for Project Cloak because:

- IBM's approach explicitly does **not** preserve the ability to reverse-map the LLM output back to original identifiers (stemming is lossy)
- IBM's approach is designed for **natural language PII**, not source code identifier obfuscation
- The statistical topic-model approach produces output that is semantically similar but structurally dissimilar to the input — the opposite of what AST-aware obfuscation requires

**Combined 103 risk:** An examiner could potentially combine IBM's "strip PII before LLM" concept with Acronis's "replace with dictionary tokens" concept and argue the combination renders Project Cloak's general approach obvious. The AST structure, compilation validity, semantic key, and compile-gate specifics would be the differentiating claim elements.

**How to differentiate (attorney to validate):**
- Same elements as Acronis differentiation (AST, compilability, patch output, semantic key, compile-gate)
- Additionally: "deterministic reversible mapping" (bidirectional SymbolMap) vs. IBM's lossy statistical normalization
- "Preserving syntactic structure of the programming language" as a specific claim limitation

## Filing Note

Priority date September 13, 2023. Predates all Determinex disclosures. Prior art under 35 USC 102. Differentiation strategy required as described above.
